# Codebase Cartographer

An interactive Python codebase map with a source-grounded assistant. Analyze a local repository, search its symbols, ask a question, and click an answer citation to inspect source and highlight the matching node.

## Run

```bash
uv sync
uv run uvicorn codemap.api:app --reload --port 8000
```

Open http://localhost:8000 and enter a local Python repository path. Start with the bundled `tests/fixtures/sample_pkg` directory if you want a small example.

### Enable AI chat

Copy `.env.example` to `.env` (`Copy-Item .env.example .env` in PowerShell). Set `OPENAI_API_KEY` and `CODEMAP_MODEL`, then restart the server. The existing default is `gpt-4o-mini`; use a model with tool-calling support. For Gemini or Anthropic, supply the corresponding key and a supported provider-prefixed LiteLLM model ID. See [LiteLLM tool calling](https://docs.litellm.ai/docs/completion/function_call).

The UI reports whether a provider key is configured. Chat sends your question, up to eight recent conversation messages, and retrieved Python source excerpts to the configured model. Analysis and browsing do not send source to the model. Keep the server bound to localhost and analyze repositories you are authorized to read.

Without a key, chat returns labeled local search results with real source citations. It does not pretend those results are an AI explanation. Provider errors, invalid citations, and retrieval budget exhaustion also fall back to local evidence with an explicit reason.

## Main workflow

1. **Analyze:** build the graph and retain a server-side source snapshot.
2. **Search/select:** find a symbol or click the map to set the chat context.
3. **Ask:** try “Where are the entry points?”, “What does Calculator.compute do?”, or “Who calls this selected function?”
4. **Inspect:** click `[S1]` or a source chip to show its original lines and highlight the corresponding graph node.
5. **Follow up:** recent conversation is supplied as context; each answer retrieves fresh evidence. Clear the selected node to ask about the whole repository.

The map initially shows modules for larger repositories. Arrange uses a spaced grid for readable node positions; detail filters, relationship filters, zoom and focused subgraphs support exploration. Chat remains usable if the map library cannot load.

## Architecture

```text
src/codemap/
  parser/ast_parser.py  Python AST nodes, lexical/import bindings, conservative calls
  parser/models.py      Graph dataclasses plus server-side source snapshots
  graph/builder.py      NetworkX layout, centrality and graph serialization
  knowledge.py         Bounded symbol search, source reads and graph traversal
  llm/chat.py           LiteLLM tool loop, citation checks and local fallback
  llm/narrator.py       Original optional per-node narration
  api.py               Analysis cache, chat and source endpoints
  static/              Map, chat and source inspector (HTML/CSS/JavaScript)
```

The chat model has five read-only tools: `search_symbols`, `get_node`, `get_neighbors`, `read_source`, and `find_paths`. It cannot run shell commands, execute repository code, change files, or invent stored graph relationships. Search uses names, docstrings and source keywords; there is no embedding index or vector database.

Each answer is bounded to four model requests, twelve tool calls and a 50-second request budget (individual provider calls have shorter timeouts and retries disabled). Source reads are limited to 80 lines / 6,000 characters, with at most 24 citation excerpts. Broad traversals return truncation indicators.

Citation IDs and line ranges are generated by the retrieval layer, not trusted from model output. Responses with missing or invented citation IDs fall back to retrieval results. **This validates citation identity, not semantic entailment:** an LLM can still misinterpret cited code. Facts, hypotheses and incomplete static relationships must remain distinguishable.

## API

- `POST /api/analyze` — `{ "path": "..." }`; returns the graph and `analysis_id`.
- `POST /api/chat` — `{ "analysis_id": "...", "question": "...", "selected_node_id": null, "history": [] }`; returns an answer, source citations, highlight node IDs and the answer source.
- `GET /api/source?analysis_id=...&node_id=...` — source excerpt; optional `start_line` pages within that symbol.
- `POST /api/explain` — legacy node narration; pass `analysis_id` and `node_id`.
- `GET /api/health` — provider-key availability and configured model.

The eight most recently used analyses are retained in one server process. IDs prevent another tab's analysis from changing chat/source context. Source excerpts remain those read during analysis even if files change on disk; re-analyze to refresh. Restarting the server or cache eviction requires a new analysis. Use one Uvicorn worker. The legacy `/api/explain` endpoint still accepts an omitted analysis ID for compatibility; the browser uses analysis IDs throughout.

## Analysis limits

- Python only, including ordinary flat packages and conventional `src/` layouts.
- Calls resolve through lexical definitions and explicit import/module aliases. Duplicate short names do not produce guessed cross-repository calls. Nested functions and recursion are represented.
- Dynamic receiver types, inheritance dispatch, callback values, wildcard re-exports, complex assignment/control flow, lambdas and comprehension scopes are not fully resolved. Such calls can remain unresolved. Constructor calls can target a class node.
- A missing edge does **not** prove that a change has no impact. No exhaustive change-impact guarantee is made.
- Degree centrality is a structural heuristic, not a validated measure of conceptual importance.
- Cytoscape 3.30.2 and its MIT license are bundled locally. The map, parsing, tests, retrieval and source inspection work without network access. AI responses require the configured provider connection.

## Validation

```bash
uv run pytest
uv run python evals/run_evals.py
```

Tests cover parser regressions, scope/import resolution, snapshot isolation, API validation, actual citation ranges, source restrictions, bounded tools, a mocked multi-step model exchange, invalid model responses, and provider failures. They do not require live model requests. Actual answer quality and provider compatibility should be evaluated with your chosen model and representative repositories.

The existing evaluation harness measures entry points and centrality on one hand-labeled sample repository. Run it for the current results; it is illustrative, not evidence of broad call-graph accuracy.


## Explore, trace and compare

- **Potential impact:** select a symbol and choose “What depends on this?”. Inspect direct and transitive resolved callers (one to six hops), file importers shown separately, and test functions in dependent files. Test candidates are not proof of coverage. Traversal is bounded to 200 nodes and reports truncation.
- **Call flow:** “Trace calls” follows outgoing call relationships. “Find a call path” finds one directed path of at most eight edges to another symbol. These are possible static paths, not runtime traces or guaranteed execution order.
- **Relationship evidence:** click a graph edge or an inspector relationship to inspect the exact source statements. Repeated call sites are retained; the UI shows up to twenty locations.
- **Compare analyses:** re-analyze the same repository after edits, then choose an earlier cached snapshot in Explore. Added, removed and changed symbols and relationships are listed. This compares in-memory source snapshots, not Git revisions. A method edit also changes its containing class and module source.
- **Overview:** entry points, resolved caller counts and strongly connected module-import groups help orient you. These are structural observations, not automated defect reports.
- **Diagnostics:** unresolved calls and file parse failures link to source where available. Diagnostics are capped at 1,000 in the API and 60 in the initial UI list.
- **Saved places:** bookmark selected symbols in this browser, scoped to the repository. They persist across re-analysis. No source or credentials are stored in bookmarks. The last path is also remembered locally.
- **Exports:** download the graph JSON or a self-contained investigation containing the last fifty answers, their source citations, overview and selection. Files are saved locally by the browser. Keep exported source evidence private when appropriate.

The interface has separate Explore, Map, Inspect and Ask views on narrow screens. Wide screens show the explorer, map and a tabbed inspector/chat panel. Source and result lists scroll within their own panels.

### Start reliably on Windows

Run `.\start.ps1` from this project in PowerShell. It starts the server at http://127.0.0.1:8767 and must remain open. Press Ctrl+C to stop. Use `.\start.ps1 -Port 8000` to select another port. Restart after editing `.env`. The app detects backend disconnection and provides a Reconnect action; it cannot start a stopped Python process from the browser.

A `.env` file was created with an empty API-key field. Supply your own provider key to enable AI; do not commit credentials. `.env` is already ignored by Git.

### Additional endpoints

- `GET /api/explore?analysis_id=...&node_id=...&mode=impact|flow&depth=3`
- `GET /api/relationship?analysis_id=...&source_id=...&target_id=...&relationship=calls|imports|contains`
- `GET /api/path?analysis_id=...&source_id=...&target_id=...`
- `GET /api/analyses` lists cached snapshot metadata, without source.
- `GET /api/compare?before_id=...&after_id=...` compares the same repository's snapshots.
